# Roadmap

`skillz` is a passive AI-skill instruction and reference repository. Core implementation is complete.

## Current milestone: governed curation mode

There is no standing core implementation backlog.

The repository now stays useful through occasional curation:

- discover promising first-party, official, or community skill sources when useful;
- independently decide whether a source or individual skill adds differentiated value;
- preserve provenance, author, license, path, exact revision/identity, dependencies, authority, portability, and required components;
- assign controlled metadata and a decisive semantic quality state;
- reject, retire, adapt, compose, extract, or retain as reference where appropriate;
- reconcile historical review evidence into current companion records when worthwhile;
- refresh review when materially changed content is intentionally reconsidered.

The living source-by-source state is [`CURATION_QUEUE.md`](CURATION_QUEUE.md). That ledger is intended to remain visible evidence of the repository's depth and active frontier.

## Corpus posture

The repository deliberately maintains three useful layers:

1. **42 first-party skills** under `skills/`;
2. a **500+ pinned reference surface** including 12 exact-revision external corpora under `vendor/`;
3. a narrower governed third-party shelf with individual provenance and semantic review companions.

Pinned availability is not blanket trust. Individual verification is not a requirement for a source to remain useful reference material.

## Evaluation posture

Repository evaluation is best-effort semantic review of instructions, skill packages, provenance, and governance data.

The repository owns:

- clarity and coherence of instructions;
- complete preservation of legitimate skill-owned components;
- useful provenance and metadata;
- reasonable quality review of material it deliberately governs;
- explicit boundaries between unchanged reuse and reference evidence;
- adversarial review for obvious ambiguity, overreach, contradiction, and misleading completion claims.

The repository does **not** own or guarantee the capability of the model reading it. There is no requirement to benchmark multiple models, hit behavioral success metrics, prove weaker-model performance, run CI, execute tests, or maintain runtime machinery.

## Durable design rules

1. Compare before creation; user-fit before reuse.
2. Prefer the smallest useful coherent set over maximum skill count.
3. Availability and source reputation are not individual verification.
4. Exact-version identity matters for reviewed third-party material.
5. Attribution and licensing obligations travel with third-party material.
6. Engine procedures do not count as user-facing library inventory.
7. Pinned corpora are broad reference material; individually governed records carry stronger unchanged-reuse evidence.
8. A skill's own scripts, references, templates, fixtures, examples, and other required components remain part of that skill package.
9. Installation or precise portable handoff is part of the user result.
10. Returning users are refined, not reset.
11. `NO CHANGE NEEDED` is valid.
12. Semantic review is probabilistic and honest about its limits.
13. Do not reintroduce CI, runtime proof, repository-engine executables, or perpetual completion gates.

## Future curation does not reopen core completion

Adding or evaluating another good skill next month, next quarter, or next year broadens the ecosystem. It does not mean this repository was unfinished today.

The intended steady state is simple: the engine remains stable, the reference corpus remains useful, and the curation ledger occasionally grows when worthwhile material appears.
