## Reproducible technical findings

1. **PTX instruction floor (F1).** The INT8 author's Turing `sm_75` minimum for `dp4a` is false. NVIDIA PTX ISA explicitly requires **`sm_61` or higher** for `dp4a`; individual devices/toolchains and optimization pathways still need checking. This says nothing about whether a particular Pascal GPU will outperform a library or newer tensor-core path. [NVIDIA official PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/).
2. **Scalar versus GEMM error (F2).** For finite uniform round-to-nearest symmetric quantization with positive scale `s`, no clipping and sufficiently precise arithmetic, `|x - dequant(quant(x))| <= s/2`. It is **not** `s/254`. A dot product quantizing *both* operands requires error propagation. The CPU control with `a=[127,0.49]`, `b=[127,127]`, scales `1,1` gives FP dot **16191.23** versus quantized/dequantized dot **16129**, an error **62.23**. The incorrect quoted output bound evaluates to approximately **0.00394**. A valid but conservative no-clipping bound for the corresponding exact-real dot is the sum of `|a_i|*sb/2 + |b_i|*sa/2 + sa*sb/4`; it is *not* an FP32 accumulation/output-rounding guarantee. Clipped or asymmetric quantization needs its own scheme-specific analysis.
3. **Accumulator overflow.** For signed symmetric inputs limited to `[-127,127]`, the largest K with the conservative `127*127*K <= INT32_MAX` condition is **133144**, and the first mathematically overflowing K is **133145**. K=131072 does **not** exceed this bound. For possible `-128 * -128` products, the safe threshold instead becomes **131071**. An asymmetric zero-point correction must account for signed centered values, not blindly reuse `127²`. Split reductions or wider accumulation when necessary; changing scale granularity by itself does not reduce K.
4. **Misstated traffic and empirical performance.** A 128×128 INT32 intermediate occupies **65,536 bytes** (64 KiB), and its write plus read is **131,072 bytes** (128 KiB), not the proof's ~2 KB. The analogous 512×512 round-trip is **2 MiB**. The quoted speedups are upstream assertions, never observed on our GPU/toolchain. One NVIDIA architecture's peak throughput ratio is not an unconditional runtime target.
5. **Dequant group crossings.** For a Triton tile with `BLOCK_K=64`, `GROUP_SIZE=96`, the tile starting at `k=64` crosses group index 0→1 **even though `BLOCK_K <= GROUP_SIZE`**. Checking length alone is insufficient. Require a per-element group-index mapping, including non-divisible K tails, or a proven tile alignment restriction.
6. **Per-group comparison and scheme handling.** Triton's suggested global comparator `atol=scale.max()/2` can hide serious errors for a smaller-scale group. For scales `0.01` and `100`, the global tolerance is **50**; an error of **20** in the small-scale group would pass the absolute threshold despite being thousands of local half-steps. Compare **scheme-matched reference dequant** element-wise with dtype/operation-rounding justification and separate local group tolerances, not an input quantizer's half-step bound. Packing permutations, NF4 table, GPTQ `g_idx`, integer zero-point convention, and group layout are version-specific rather than a universal algorithm.
7. **Debugging authority.** The debug source's requirement to name one root cause and deliver a fix should allow `INCONCLUSIVE / evidence insufficient / execution not authorized`. Source excerpts are not a mandate to edit user files, compile kernels, or run foreign code.
