# Skillz Workbench

Static, client-side guided experience. No account connection, telemetry, local storage, backend or automatic skill installation. The browser uses a bundled snapshot of the authored index and governed name index; the optional Refresh button fetches only public registry JSON and sends no task or selection data. The name index is not the full corpus. The agent handoff explicitly requires expanded discovery and exact-source qualification.

Value estimates are user assumptions, not observed performance or guaranteed monetary returns. Same normalized task labels are treated as overlapping; the conservative total takes the largest positive gross benefit per label, all negative effects and all setup/upkeep costs. Distinct labels can still overlap. No totals for unconfirmed assumptions. Qualitative outcomes (quality, risk, consistency, learning) and user-defined evidence remain separate from time estimates. Users may sort the shortlist by estimated net time or payback without pretending every benefit is monetary.

Single and phased blueprint JSON follows the existing engine v1 shape. Pack designs are handed to the agent rather than manufacturing a module graph. The browser does not run the engine or test target-host execution; the handoff directs the agent to the canonical Bootstrap and host guard. Browser validation is preliminary.

Publish from main root or /docs in GitHub Pages settings; both have landing entrypoints. Workbench files are in docs/workbench/. No account settings are changed by this repository. To serve locally, use an approved static file server rooted at docs or open docs/workbench/index.html. To run deterministic offline checks: node docs/workbench/test.js. The first-party source index snapshot can be regenerated from the two named registry JSON files; the refresh button supports newer public source data. Browser and live deployment acceptance remain separate from offline tests. The publication policy excludes all paths except the Workbench entrypoints and first-party assets. Distributed LICENSE.txt includes the original MIT notice; RIGHTS.txt explains that catalog references confer no upstream reuse rights. The published scope must not include upstream packages or their contents.

Authored value cards are editorial summaries of each first-party MIT SKILL.md description at the pinned snapshot, bound to its exact blob. Example success measures are proposals, never measured ROI. Refresh retains a card only when the source blob is unchanged; changed or new packages require fresh review. Search matches include these benefit and measure terms; matches explain their lexical basis, not model-based relevance. Third-party identifiers never receive inferred benefit cards.

The optional context step is a worksheet, not an assessment engine. Search uses literal keyword matches, never inferred intent, host fit or personalized recommendations. No required questions precede browsing; advanced context can be supplied optionally. The browser compares user-confirmed value assumptions and exports a plan for an actual agent to evaluate. It does not choose, execute or install skills.
