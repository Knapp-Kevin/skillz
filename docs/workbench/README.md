# Skillz Workbench

Static, client-side guided experience. No account connection, telemetry, local storage, backend or automatic skill installation. The browser uses a bundled snapshot of the authored index and governed name index; the optional Refresh button fetches only public registry JSON and sends no task or selection data. The name index is not the full corpus. The agent handoff explicitly requires expanded discovery and exact-source qualification.

Value estimates are user assumptions, not observed performance or guaranteed monetary returns. Same normalized task labels are treated as overlapping; the conservative total takes the largest positive gross benefit per label, all negative effects and all setup/upkeep costs. Distinct labels can still overlap. No totals for unconfirmed assumptions. Qualitative outcomes (quality, risk, consistency, learning) and user-defined evidence remain separate from time estimates. Users may sort the shortlist by estimated net time or payback without pretending every benefit is monetary.

Single and phased blueprint JSON follows the existing engine v1 shape. Pack designs are handed to the agent rather than manufacturing a module graph. The browser does not run the engine or test target-host execution; the handoff directs the agent to the canonical Bootstrap and host guard. Browser validation is preliminary.

Publish from main root or /docs in GitHub Pages settings; both have landing entrypoints. Workbench files are in docs/workbench/. No account settings are changed by this repository. To serve locally, use an approved static file server rooted at docs or open docs/workbench/index.html. To run deterministic offline checks: node docs/workbench/test.js.
