# Balanced capability quality plan

Established November 17, 2026 from the audit of `660da7ca95503a3756179cc3a725d4b667e110b3`. Prepares the passive corpus for a separate capability-oriented application. It does not create that application or establish uniformly effective domain packs.

## Completion standard

Equal service means equal evidence standards for essential outcomes, not equal file counts. Each essential workflow needs explicit inputs, outputs, prerequisites, correctness criteria, dependencies, failure handling, authority boundaries and an exact-version source/rights decision. The future application owns its executed acceptance evidence.

Track discovery leads, complete-package inspection, static disposition, dependencies, license/asset rights, portability, authority/privacy limits and behavioral evidence separately. Keep unknown, rejected, reference-only and not-run visible. An aggregate score must not hide an unmet essential outcome or unresolved rights.

## Outcome receipt

Record domain/subdomain, outcome, essential/optional decision, exact candidate identities, inspected package boundaries, comparison rationale, rights/asset restrictions, dependencies, portability, authority/privacy limits, static disposition, unresolved gaps, original review date and later freshness checks. Include failure criteria and a next action for unmet outcomes. Record observed application results only when actually executed.

New third-party admission follows issue-first intake. Formatting repair is not candidate admission. Do not bulk-copy candidates, create a new repository or advertise complete domain packs before scope and rights are established.
