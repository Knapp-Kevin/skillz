## Source-level functional difference

The prior authored version was stronger than the original at
recognizing code-context markers, tying changes to real defects,
avoiding deletion by age alone and admitting partial search
coverage. However it did not require the older **marker harvest**
deliverable: per-token type counts, line-level age evidence,
cluster density and median age, user-facing quick-repair/ticket/
obsolete-candidate categories, or compact large-inventory
presentation. This could turn an explicit harvesting request into
an abstract risk-only assessment.

preserving full root-cause triage. Line edit time is distinguished
from underlying defect age. Safe repository API inspection is
preferred over uncontained local Git execution. New types and
old comment contents are untrusted evidence, not instructions.
The skill remains strictly report-only.
