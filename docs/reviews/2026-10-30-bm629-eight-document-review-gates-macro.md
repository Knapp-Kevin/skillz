## Systemic findings and cautions

1. **Differentiation:** the reviewing gates are not eight prompt wrappers for the same task. API reference checks consumer-facing contract drift; API spec checks wire-level completeness; architecture checks system boundaries/ADRs; data model checks persistence/query integrity; design system checks tokens/components/accessibility; developer guide checks adoption and runnable sample accuracy; feature spec checks behavior/acceptance; PRD checks problem/scope/plannability. Their matching authoring siblings are dependency/context, not replacements for an independent reviewer.
2. **Single-sourced-bar drift:** five SKILL.md files add a conditional `capability_record` condition not reflected in their bundled older count descriptions: API spec 11→12, architecture 10→11, data model 9→10, feature spec 10→11, PRD 12→13. The condition explicitly becomes N/A when no record is supplied. This is not a side-effect hard fail, but it weakens the claim of a literally single-sourced bar; the exact pinned SKILL.md controls and adaptation should reconcile both surfaces before operational adoption.
3. **Privacy/authority:** review inputs can be sensitive product, architecture or customer documents. These procedures do not authorize broad connector searches, publishing, external model disclosure or secret handling. Use only explicitly supplied/authorized context and redact evidence excerpts; the user/host must authorize any external transmission separately.
4. **Evidence:** source `references/sources.md` files provide methodology attribution, not live executed tests. Claiming samples are runnable or architecture matches reality requires actual supplied evidence; no host execution was performed. The DTCG and numeric accessibility floors in design-system review may be overly rigid for small projects.
5. **Value and priority:** source has unusually coherent author/reviewer pairs and evidence-gated outcomes. Continue the remaining review-gate/authoring cluster ahead of provider-ops material when quality and source priority warrant it. Do not promote the 58 remaining gaps, the source as a whole, or any unchanged package without exact-version security/user-fit qualification.
