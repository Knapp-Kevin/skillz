### Individual use, dependencies, authority and adaptation value

1. **`figma-code-connect`**: trigger Figma component-to-code mapping, not general UI generation; parserless `.figma.ts` template workflow with two reference files. Requires published components, Figma MCP, local codebase and `figma.config.json`. It asks the user to confirm the component match before writing, and checks template type/props after writing. Authority: `mutating` local code; confirm exact repository/path and no unintended publication. Portability **medium**; tags `implementation`, `documentation`, `evidence-first`. **REFERENCE-ONLY** for unusually precise mapping/validation, terms block copying.
2. **`figma-create-new-file`**: trigger new Design/FigJam/Slides file or automatic prerequisite; no bundled references. `whoami` selects a single plan automatically and the procedure immediately creates a persistent draft even when file creation is merely an internal prerequisite. Authority: `external-side-effect`; exact plan, editor, filename and creation need explicit scope. Portability **low**; tags `prototyping`, `planning`, `risk-aware`. **REJECT unchanged** for inadequate action-specific creation authorization; preserve the plan-resolution decision tree.
3. **`figma-design-to-code`**: trigger Figma-to-code implementation, not code-to-Figma; requires `get_design_context`, local project, asset URLs and token/component reuse. The asset download-and-commit instruction lacks an independent rights/privacy check. Authority: `mutating` project and potentially external asset reads. Portability **medium**; tags `implementation`, `ux`, `source-driven`. **REFERENCE-ONLY** for component/token reconciliation and screenshot parity, with explicit asset rights and destination approval required before adaptation.
4. **`figma-generate-design`**: trigger code/description-to-Figma screen construction, not component mapping; two bundled references plus `figma-use`, design libraries and sometimes `generate_figma_design` capture. Mandatory parallel web-app capture for image-containing views can disclose private pages/assets and produce persistent design mutations without independently scoped consent. Authority: `external-side-effect`; portability **low**; tags `ux`, `implementation`, `visual-verification`. **REJECT unchanged**; retain token-first assembly and section screenshot checks.
5. **`figma-generate-diagram`**: trigger Mermaid/FigJam diagrams; seven type-specific references. Broad mandatory trigger reaches generic diagram requests; a missing `fileKey` creates a new persistent FigJam file, and replacement suggests deleting old nodes. Authority: `external-side-effect`; portability **low**; tags `architecture`, `documentation`, `risk-aware`. **REJECT unchanged**; preserve diagram-type routing, Mermaid constraints and iteration limits.
6. **`figma-generate-library`**: trigger Figma component/variable/library creation; seven reference files and eight upstream JS helpers. Phase 0 explicitly scopes a plan and asks for approval, a real strength. But later automatic multi-phase writes and `cleanupOrphans.js` node/variable/collection deletion need a separately bounded destructive authorization; a saved ID ledger is not consent. Authority: `external-side-effect`; portability **low**; tags `architecture`, `ux`, `traceable`. **REJECT unchanged**; extract token-first sequencing, exact-ID ledger and phase acceptance without inheriting deletion behavior.
7. **`figma-implement-motion`**: trigger Figma animation-to-code, not editing Figma motion; six references and `get_motion_context` plus `get_design_context`. Strong exact-node/keyframe matching and no fabricated motion. Local code writes and remote asset use still require scoped rights and authorization. Authority: `mutating`; portability **medium**; tags `implementation`, `ux`, `evidence-first`. **REFERENCE-ONLY** for timing fidelity and single-animation validation.
8. **`figma-swiftui`**: direction router for SwiftUI/Figma, not generic web work; two direction-specific references, Figma MCP, Xcode/SwiftUI conventions. It asks when direction is ambiguous and maps iOS semantic tokens. Code-to-design branch can mutate external Figma state. Authority: `external-side-effect` for that branch; portability **low**; tags `implementation`, `ux`, `compatibility-aware`. **REFERENCE-ONLY** for direction separation and HIG token mapping.
9. **`figma-use-figjam`**: FigJam-specific API procedures, not Design-file `createPage`; thirteen reference files and `figma-use`. Correctly flags unsupported APIs and requires `get_figjam` before editing existing nodes; `upload_assets` can disclose local images and edits persist. Authority: `external-side-effect`; portability **low**; tags `ux`, `documentation`, `tool-routing`. **REFERENCE-ONLY** with file, data and mutation scope separately approved.
10. **`figma-use-motion`**: animation keyframe API reference, not static Figma editing; two references and `figma-use`. Accurate `metronome` feature-flag fail-fast and `export_video` rendering cost caveat, but no separate spend/disclosure approval. Authority: `external-side-effect`; portability **low**; tags `ux`, `implementation`, `cost-bounded`. **REFERENCE-ONLY** for feature gating and minimal-frame verification.
11. **`figma-use-slides`**: Figma Slides editing/inspection, not ordinary Markdown slides; six references, `figma-use`, Slides Plugin API. Explicitly warns not to delete existing slides and provides slide-grid and visual validation. It can read speaker notes and mutate persistent deck content; permission to view one slide is not blanket private-notes access or deck rewrite. Authority: `external-side-effect`; portability **low**; tags `communication`, `ux`, `visual-verification`. **REFERENCE-ONLY** for deck structure and non-destructive edits under scoped approval.
12. **`figma-use`**: generic arbitrary Plugin API JavaScript execution in Figma files, including node creation/deletion, variables and styles; 20 bundled reference blobs. It has excellent API failure-handling and exact-ID verification but no universal action-specific authority check before arbitrary persistent writes. Its asserted atomic error semantics should be treated as source claims, not independently validated guarantees. Authority: `external-side-effect`; portability **low**; tags `implementation`, `ux`, `tool-assisted`. **REJECT unchanged**; preserve API gotchas and inspect-before-write methods, never treat availability of `use_figma` as authorization.
