## Macro findings and omissions

1. **Strongest differentiated mechanism:** one structured result schema separating static token estimates from observed usage, `checks[]`/`metrics[]`/`artifacts[]`, a prioritized improvement brief and before/after comparisons. This is worthwhile as **reference design** for external host agents, not a reason to install a CLI into the passive corpus.
2. **Highest authority failure:** a manifest-selected metric pack is executable code, not a harmless rubric. The actual runner inherits process environment and passes target identity; the skill omits an authorization, code-review, sandbox, egress and credential gate. Independently, the live benchmark uses credentials and billable Codex execution without the necessary explicit scope.
3. **Privacy/retention:** the benchmark copies private workspace material and Codex authentication/configuration into temp directories, persists raw event logs/final messages, and can retain failed workspaces. `--ephemeral` on the Codex command does not erase the host's persisted artifacts or the source-owned benchmark directory.
4. **False assurance and documentation drift:** `--dry-run` is shown in two skill procedures but the pinned implementation rejects it; manifest `0.1.2` and CLI package `0.1.0` are distinct; the technical design's V1 static-only/non-benchmark description is stale relative to the current executable benchmark implementation. Do not present a static structural score as a security or behavioral pass.
5. **Overlap:** the five share one CLI, schema and references, with heavy trigger overlap between `plugin-eval`, `evaluate-skill` and `evaluate-plugin`. Existing `skillz` verification/security guidance and draft [#413](https://github.com/Knapp-Kevin/skillz/pull/413) cover much of the method. The differentiated benefit is a **schema and analysis workflow**, not five new user-facing skills or a separate repository runtime.
6. **Source-family priority:** the official Plugin Eval slice is exhausted at **5/5 candidate decisions**. Prioritize independent qualification of the 36 changed first-party packages before expanding into more evaluation wrappers; other official plugin families remain discovery leads, not admitted denominators.
