## Cross-family systemic findings

1. **Critical crypto-example quality defect:** The four-byte DEK in `azure-keyvault-keys-rust` is not a minor documentation omission. An agent faithfully copying the example can build an envelope-encryption scheme with trivial brute-force resistance despite using Key Vault for the wrapping operation. Secure infrastructure branding does not rescue insecure plaintext key generation.
2. **Secret egress from primary examples:** `azure-identity-rust` and `azure-keyvault-secrets-rust` encourage printing live secret values, which can enter logs, terminals, transcripts or host-agent context. The appropriate repair is a secure credential handle, not a more emphatic warning.
3. **Data and lifecycle authorization absent:** Cosmos, Event Hubs, Key Vault, Blob and Queue examples cross resource, privacy, billing or destructive boundaries with no explicit user-approved scope. RBAC and valid credentials are necessary operational prerequisites but not sufficient action authorization.
4. **Useful Rust SDK differentiation:** The eight are not mere prompt aliases. Their official-crate selection, typed client patterns, version-aware operations, error handling and Rust credential caveats are useful extraction references when combined with stronger host authorization and data minimization.
