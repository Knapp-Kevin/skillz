## Cross-package synthesis

1. **Two bounded semantic positives.** `azure-resource-lookup` (16/20) and `azure-resource-visualizer` (16/20) remain read-only against Azure. The visualizer explicitly asks for resource-group selection, substitutes placeholders for secrets and prohibits Azure mutation. The lookup bounds Resource Graph output and excludes mutation. Both are VERIFIED **semantic only**, with package-security not-run and host-specific user/subscription scope, topology disclosure and local-document destination still requiring authorization at use time.
2. **Secrets and security posture.** `azure-compliance` references `keyvault_secret_get` and `az keyvault secret show`, which may expose secret values instead of only expiry metadata. Its bundled `azqr-remediation-patterns.md` contains live network, storage and Key Vault mutations without a separate authorization gate. Reuse only a metadata-only audit/checklist adaptation; do not treat credential availability as approval.
3. **Telemetry/credentials.** `appinsights-instrumentation` claims guidance-only routing but instructs resource creation, app edits and logging. Its Container Apps reference obtains a Log Analytics shared key, while source-owned examples transmit telemetry. Collection scope, data minimization, recipient, retention, consent and key custody are not established. These are unchanged-use hard fails.
4. **Cloud quota and storage mutation.** `azure-quotas` provides `az quota update`, provider registration and extension installation without owner consent; source-owned quota scripts perform read queries but install an extension. `azure-storage` includes blob upload/download and SDK message deletion patterns without data-scope, overwrite, deletion or disclosure authority. Preserve comparisons and command syntax as adaptation prior art.
5. **Operational read disclosure and remediation.** `azure-kusto` can query/join sensitive telemetry and private logs across workspaces without dataset/disclosure approval. `azure-messaging` ends with “apply remediation” without a scoped change permit and has no credential-string redaction rule. Read-only diagnosis is useful; live fixes need a separate approved action.
6. **Shared quality signal.** Official authorship, an MIT manifest, a valid Azure credential and an available tool are not sufficient action authorization. The strongest reusable methods are source-specific routing, bounded query planning, exact resource-scope selection, Mermaid topology documentation, quota-name mapping, metadata-only compliance and storage tier comparisons. The eight do not warrant new taxonomy terms or automatic source admission.
