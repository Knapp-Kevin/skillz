## Why these are hard fails
**Inputs, credentials, parameter confirmation and tool access are not permission to act.** An explicit approval for a later destructive action does not retroactively authorize creating a change set, IAM role, ECS cluster, budget, or Bedrock resource. Nor does permission to enable monitoring automatically authorize private deployment metadata egress. The six corrected skills have useful patterns, but unchanged use would require an adapted procedure with an affirmative pre-effect gate: exact account/region/resources, financial and network effects, data categories, telemetry destination/retention, recipients and rollback/destructive scope as applicable. Missing authorization means proposal-only.

**Evidence quality and freshness:** AWS service quotas, APIs, model support, pricing and instrumentation semantics change. Original exact package identities and dependency descriptions remain in each provenance companion. Existing source and package tree fingerprints are retained; no independent package-tree recomputation, live AWS action, SkillSpector scan, or adversarial execution is claimed. Every behavioral state remains `not-run`. No literal secrets, customer data or credentials were handled.

**Useful retained prior art:** IAM least privilege and PassRole guidance; deterministic cost math and date-aware billing; CloudFormation validation and template injection defense; Bedrock guardrails and ingestion privacy; ECS deployment rollback/secret injection; CloudWatch/ADOT troubleshooting; Clean Rooms permission debugging; Secrets Manager runtime-only resolution; SAM/CDK architecture and boto3 patterns. REJECT unchanged is not REJECT all knowledge.
