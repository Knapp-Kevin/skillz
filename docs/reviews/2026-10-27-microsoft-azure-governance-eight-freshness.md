## Macro findings

1. **The proof oracle is the sharpest defect.** The `azure-validate` helper accepts `--completed-step UpdateStatus` and writes `.azure/validate-status.json` without verifying any command output or validation proof. The skill tells the agent to mark the plan `Validated` after following the helper, and `azure-deploy` consumes that status as a prerequisite. A claimed workflow completion is not independent proof of validation. This is a **static source inspection**, not an observed exploit.
2. **Cloud read access is not unlimited disclosure permission.** The Key Vault fallback can retrieve secret *values* when only expiration metadata is needed. Resource lookup and visualization can reveal cross-subscription inventory, RBAC relationships, network topology and configuration. Restrict tenant/subscription/resource scope, minimize fields and control where artifacts are persisted.
3. **Billing requires its own authority.** Capacity Reservation Groups can accrue charges before any VM uses the reserved capacity. The compute creator's live-MCP confirmation does not automatically authorize the separate CRG path. No cost-bearing command was executed.
4. **Preserve good gates rather than flattening the family into rejection.** The enterprise planner explicitly requires risk-acknowledged consent after presenting deployment risk, shows validation/Checkov evidence and protects referenced resources from destructive recreation. Azure reliability stages approvals for quick fixes, storage conversion and multi-region changes. These are high-value **EXTRACT/ADAPT** mechanisms even while full-package security and dependency closure remain pending.
5. **Shared plugin-level privacy exposure matters.** The *upstream* `.github/plugins/azure-skills/hooks/copilot-hooks.json` (`bac46f27aa874e2b8e53dbaba07da3e3ad8f1dcb`) invokes `track-telemetry.sh` on `SessionStart` and `PostToolUse`. Its script (`abd2ee3998f2304840386faa98c32aacaba1d2bc`) skips telemetry when `AZURE_MCP_COLLECT_TELEMETRY=false`, otherwise may install a source-owned reporter; when `AZURE_SKILLS_TELEMETRY_LOG_DIR` is set it can persist raw hook input locally. These are **source-owned plugin files, not `skillz` runtime**. Standalone SKILL.md screening cannot qualify installation of the enclosing plugin or authorize telemetry/retention.
6. **Overlap is substantial but not total.** `azure-compliance`, `azure-resource-lookup` and `azure-resource-visualizer` share Azure Resource Graph discovery; `azure-validate` and `azure-deploy` share a plan-status handoff; `azure-compute`, `azure-enterprise-infra-planner` and `azure-reliability` overlap on IaC and live infrastructure but have distinct intent routing. Do not duplicate reference-only ARG patterns as three independently trusted permissions.
