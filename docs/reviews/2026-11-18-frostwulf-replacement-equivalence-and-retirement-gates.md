# Frostwulf replacement equivalence and retirement gates

Date: 2026-11-18. [PR #736](https://github.com/Knapp-Kevin/skillz/pull/736).

## Outcome reached

Every one of the **44** historical `frostwulf.zo.computer` entrypoints
has a declared replacement in the new-authored collection. This produces
**21 unique original packages**, including a six-file intelligence skill
with 17 topic profiles. Each new package was read and statically
evaluated against the 10-dimension Skillz rubric, with original synthetic
cases and exact source/package Git identity. A direct seven-word
literal-overlap comparison with each corresponding historic entrypoint
found no matches. This is **not** legal clearance or proof of global
novelty.

Historical account ownership, the Git commit author, and the historical
MIT classification of those sources do **not** independently establish
who originated the old skill text. The new skills' MIT license covers
newly authored expression only; no unknown third-party text was imported.

## Known non-parity and sensitivity hotspots

- **technology-change-intelligence:** The 17 profiles preserve intended topic distinction, but per-provider source freshness, correctness and specialized result parity require real checks.
- **personal-operations-control-board:** Legacy task-surface included task store scaffolding/mutations, while new design is read-only by default and only prepares explicitly authorized writes; do not claim drop-in parity.
- **repository-delivery-assessor:** Legacy local worktree status is not observable from GitHub metadata alone. Native packaging, CI and release acceptance are not established.
- **statement-variance-reviewer:** No real user-authorized CSV/XLS export was parsed or reconciled; transaction conversion and category correctness untested.
- **professional-market-evidence-scout:** No real employer-posting availability or compensation normalization verified.
- **business-presence-observatory:** No real forms, mobile journeys, directory listing updates or authenticated CMS operations tested.
- **context-continuation-contract:** Cross-session source authority and stale-handoff conflict cases remain scenario-only.
- **decision-tradeoff-workbench:** No actual owner criteria/weights exercise; combined modes are design-level only.
- **evidence-narrative-composer:** Public disclosure and factual claim acceptance not exercised; does not create presentation artifacts.
- **learning-evidence-progression:** Plan outcomes and learning measurement unobserved; source existence needs live checking.
- **work-period-evidence-reporter:** Git merge vs delivered outcome distinctions untested on real sources and audiences.
- **agent-failure-boundary-analysis:** No actual incident trace or causal hypothesis discrimination observed.
- **research-question-dossier:** No live multi-source research run or independence/coverage validation performed.

All remaining eight new designs also need behavior evidence when used,
especially freshness, source access, professional relevance and
audience authorization. Expected synthetic scenario outputs do not
establish actual agent-host performance.

## Retirement gate per historical source

1. **Scope and rights:** Bind the exact historical package and all
   supporting files, including `sources.json`, examples and notices.
   Preserve its original Git identity, prior review and unknown
   authorship/rights findings in a history record.
2. **Functional outcome:** Map legacy triggers, non-triggers,
   dependencies, outputs and meaningful edge cases to the new
   entrypoint or profile; explicitly accept intentional capability
   reductions rather than claiming false parity.
3. **Safety:** Recheck source-access scope, sensitive-data boundaries,
   unexpected execution paths, scheduled work, mutation grants,
   privilege escalation and prompt-injection handling.
4. **Behavior or user acceptance:** Use the replacement in a bounded
   real or representative host execution **where actual equivalence
   and user outcome are consequential**. Record inputs, exact package
   tree, observed output and negative cases. Never elevate static
   expectations to runtime PASS.
5. **Consumer and reference audit:** Identify all incoming references
   to old paths, source IDs, index keys, docs, example links, source
   listings and fixtures; update canonical and browse routes only
   when references resolve to a reviewed replacement. Preserve
   historical evidence as history, not a selectable current skill.
6. **Mutation:** Stage removal only after all exact source consumer
   checks pass. Delete the package file tree, not just SKILL.md, when
   all its assets are truly superseded. Do not delete shared assets
   or erase provenance/rights history.
7. **Verification:** At the exact resulting commit verify no broken
   links, no missing authored companions, no count/chart drift, no
   stale active selection paths, and no lost rejected-source records.
   Confirm branch/PR state and only call the work merged if the
   merge really happened.

**Current gate:** All 44 legacy entrypoints retained. No host behavior
tests established; no safe-to-delete receipts produced. A static
source review is sufficient to **publish** passive skills, but not
evidence of full behavioral parity or consumer-safe retirement.
