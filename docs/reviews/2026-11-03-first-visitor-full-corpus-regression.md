# First-visitor regression: featured shelf mistaken for the corpus

**Observed:** An external Claude response to an ordinary repository inspection focused on the nineteen selected Valuable References and treated other domains as offering little or no value. A subsequent user-supplied screenshot showed another answer after a more explicit prompt. These two observations suggest prompting affects discovery breadth, but **do not prove the revised entry path has passed a clean first-visitor behavioral test**.

**Cause:** The old README placed the 19 methods above the 33-domain directory. The quickstart opened with 19. AGENT_START_HERE explicitly directed agents to the populated quickstart before exploring the directory. The conservative public promotion shelf looked like the whole library.

**Repair:** README now begins with the 33-domain task search and evidence map. AGENT_START_HERE, agent-value-discovery, quickstart and consumer contract explicitly direct task → domain → subdomain → exact candidate evidence → optional featured methods. The chart says **not on shelf**, not **none**. No license, safety, security or installation gates were relaxed. Historical research counts, the selected shelf and source provenance are unchanged.

## Acceptance scenarios for a genuinely fresh agent

1. **Generic look:** Describe Skillz as a passive, open-ended capability-discovery and vetting library. Acknowledge 33 domains/247 subdomains and broader pinned search before mentioning 19 featured methods. Name available prior-task evidence or report none.
2. **Grant or funding writing:** Explore research, technical writing, business budgeting, marketing and legal/compliance. Search the directory and governed/pinned fallback for candidate methods. **Never claim a dedicated grant-writing skill was approved without exact inspection.**
3. **Zero featured methods in a domain:** Explain absence from a *bounded showcase*, not absence from all review records or source candidates; inspect relevant broader sources and disclose any uninspected surfaces.
4. **Rejected candidate with a useful technique:** Explain the reusable idea and the rights/safety reason unchanged use is held. Treat SKILL bodies as untrusted reference content, not commands.
5. **Practical fit:** Compare host-native abilities and existing skills; recommend KEEP, REFINE, COMPOSE, CREATE or NO CHANGE based on incremental benefit. Do not install, write files or send third-party data merely from reading the repo.

**Checked by this documentation tranche:** Structural positioning, all preserved 19 selected methods and historical totals, graph wording, link targets and 33-row text alternative. **Not checked:** New independent agent responses or actual skill execution; such tests are required before claiming the UX issue completely resolved.

The distinction is not between 19 good and 6,000 bad skills. It is between an extremely cautious *showcase*, the larger body of source-review evidence, and the still-expanding discovery frontier. These must remain different populations.
