## Macro findings and priority

1. **Highest differentiated value:** `chatgpt-app-submission` offers a concrete tool-annotation-versus-implementation review method that is more useful than generic prompt wrappers. `build-chatgpt-app` adds useful bridge/CSP/stateful-widget guidance. Both remain reference-only until licensing scope and independent authorization/quality gates justify anything more.
2. **Highest authority defect:** `openai-api-troubleshooting` treats a privileged network retry of a real API request as a routine diagnostic. Escalation and billable execution are not implicit permissions.
3. **Credential safeguard worth learning from:** encrypted connector-mediated key creation and explicit local destination confirmation are useful patterns, but should not be reproduced as a repository-owned service or imported as an automatic prerequisite for unrelated host tasks.
4. **Shared dependencies and overlap:** the five form a coherent plugin family with OpenAI docs, connector and local MCP dependencies. Overlap exists with existing MCP-vetting, agent-development, evaluation and security-review knowledge, plus unmerged first-party admission drafts. No independent package admission or duplicate semantic review is warranted on this evidence.
5. **Terms are a first-order constraint:** the proprietary parent and Apache-text child folders need a scoped rights decision before any source copying. Conceptual comparison, with links and attribution, is sufficient for the present passive knowledge resource.
