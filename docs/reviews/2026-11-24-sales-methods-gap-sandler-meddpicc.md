# Sales methodology skill gap and two original advanced packages

Date: 2026-11-24
Repository: Knapp-Kevin/skillz
Scope: targeted existing authored corpus and governed sales/GTM references,
public methodology research and original first-party authoring.
Disposition: create two separately installable, text-only methods.
All skill package examples and questions were drafted independently.

## Baseline and differentiated gap

At assessment, the canonical authored index exposed **40 first-party
packages**; none was a Sandler-specific conversation coach or an
MEDDPICC-specific opportunity assurance skill. A targeted read of the
discovery catalog also found existing third-party sales methods, including
Anthropic's `pipeline-review` record, which was **not approved for unchanged
reuse** because it mixes sales-policy assumptions with CRM mutation authority.
The source collection is larger than authored skills; absence of a first-party
package is not absence of all sales skills or proof of global novelty.

These two methods solve distinct gaps:
- `sandler-conversation-strategist`: buyer-controlled dialogue,
  problem/impact exploration, investment and decision transparency, ethical
  objections, proposal readiness and post-decision stewardship.
- `meddpicc-opportunity-assurance`: eight-dimensional complex-deal evidence,
  missing economic/process/paper/champion facts, counterevidence, fragile
  forecast inspection and bounded buyer-confirmation next action.

**Why not one blended sales engine?** Conversation skill does not
validate deal completion. Qualification skill cannot replace human-centered
discovery. Each independently works when the other is unavailable; the
optional text-only crosswalk never upgrades hearsay to buyer proof.

## Public source and rights checks

- Sandler's public [seven-step process](https://sandler.com/sandler-selling-system/)
  names rapport, up-front expectations, pain, budget/investment, decision,
  fulfillment and post-sale. Its [Terms of Use](https://sandler.com/terms-of-use/)
  assert ownership of its marks and training/course material.
- Public [MEDDPICC overview](https://meddicc.com/meddpicc-sales-methodology-and-process)
  enumerates Metrics, Economic Buyer, Decision Criteria, Decision Process,
  Paper Process, Pain and its implication, Champion and Competition.
  Some teaching uses **Identify Pain**, others **Implicate the Pain**;
  this package explicitly tests the difference rather than pretending
  the wording is universal.
- Vendor trademark/certification representations are not reproduced:
  neither package asserts affiliation, source authority or certification.
  Trademark ownership statements about MEDDPICC are contested in publicly
  available current sources, including
  [Fox Rothschild's 2026 litigation summary](https://www.foxrothschild.com/news/fox-rothschild-secures-trademark-victory-establishing-meddpicc-as-a-generic-term).
  This review does not decide legal ownership or make a clearance claim.

Only original skill instructions, original fictional cases and our own MIT
license notices are included. There are **no imported course templates**,
branded diagrams, books, PDFs, proprietary question scripts or third-party
code. A high-level published framework name is referenced as context,
not presented as owned invention.

## Adversarial architecture review before implementation

A hosted Qortara Logic route preview (caller-supplied policy, not actual
execution) proposed Plan → Deep Audit → Harden → Verify. The Qortara
verdict parser interpreted the author-led first report as **VETO**:

- **IP/dependency:** reproducing proprietary Sandler teaching scripts or
  impersonating an official coach.
- **Evidence:** computing MEDDPICC likelihood from 8 filled checkboxes or
  treating seller notes as buyer-verified deal facts.
- **Buyer autonomy:** coercive pressure or invented urgency.
- **Distinctiveness:** copying a generic pipeline review into two branded
  files without useful differentiated method.

The author-led revised PASS required two separate standalone packages,
original practical procedures, permissioned buyer evidence, explicit
no-fit/withdrawal paths, no fake probabilities/certifications, optional
limited-method crosswalk and adversarial fictional cases. The hosted
tools **did not** independently read files, perform an audit, authorize
changes or attest production behavior.

## Packaging and cross-method contracts

Each package contains `SKILL.md`, `LICENSE`,
`references/advanced-practice.md`, `examples/acceptance.md`. An isolated
offline host can execute the text procedure without Python, connected CRM,
meeting transcription, scheduling or another installed skill. A host with
actual supported authorized tools may use them independently, but selection
of a skill never grants source/account access or permission to write, send
or persist. Follow-ups preserve the current deal/conversation objective
without imagining hidden durable memory.

The shared candidate fact exchange is deliberately minimal:
`source_kind | participant_role | observed_at | claim |
evidence_locator | confidence | verification_needed | permission_scope`.
A claim transferred between skills remains the **same evidence state**;
translation cannot create a budget, champion, economic buyer or signature.

For advisory/training-service value models, a scenario worksheet is
illustrative. It must not label hypothetical uplift as actually realized.
This is compatible with future ROI calculator integrations but does not
create, inspect or alter a calculator service.

## Static review versus execution evidence

These are first-party author-led static source reviews, not independent
vendor certification or a real consuming-agent result. Scenarios are
invented expected behaviors, not executed buyer conversations or deal
forecast measurements. Code/package identity CI and GitHub review are
separately recorded at the exact PR head before merging. The governing
authored registry must retain `needs-re-review`, while host behavioral
validation and external security scanning remain `not-run` unless genuine
independent evidence is obtained.
