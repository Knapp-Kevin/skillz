## Systemic risk and value map
1. **Authority is not inherited from account selection.** Every source procedure assumes the caller injected a provider account and a capability. That is authentication/routing, not approval for a specific repo/site/job/page, action, environment, data movement, destructive state or recurring cost. All five fail the non-negotiable action authorization boundary.
2. **Secret discipline needs a second boundary.** Each credential reference instructs `set -a; source <path>/.env; set +a`, which executes shell contents from a project file rather than using a constrained secret provider. Basic-auth `curl -u "$user:$TOKEN"` expands the credential in a process argument; the GitHub example additionally passes a secret value as a CLI positional argument and `gh secret set --body` argument. Claims that only the subprocess reads a value do not prove it is absent from process lists, traces or diagnostics. Use secure external credential paths, no literal secret argv, no conversational secret solicitation, and minimize logs.
3. **High-risk overlap, distinct provider methods.** Cloudflare and Netlify cover similar static hosting, but provider-specific Direct Upload/Git, draft/prod, DNS and state-machine details differ. GitHub handles repository/identity/secret writes; Atlassian handles issue/document mutations; Jenkins handles build/job lifecycle and sensitive logs. They are not duplicate exposure paths. Reuse the differentiated mechanics only under scoped host authority.
4. **Evidence/freshness.** All five source manifests were last changed June/July 2026. Live provider API/CLI behavior, permissions, pricing and deprecations may have drifted. Bundled OpenAPI and scripts are source-owned evidence, not a skillz runtime. No new live API call, CLI command, scan or adversarial run was performed.
5. **Five remaining gaps:** `project-document-discovery`, `reviewing-document-discovery`, `reviewing-document-set`, `sql-job-queue`, `token-optimization`. Treat document discovery/private evidence and SQL mutations as separate deep-review risks; do not force a normal 8-12 quota.
