## Risk clusters identified in sampled material

1. **Identity/privacy and data migration:** `experts/bridge/identity-oauth-bridge-ts.md` (blob `a8f45f15533be3ff9ac134f20954dbe2cd3ae7f2`) proposes correlating Slack and Entra users by email, building a cross-platform identity map and re-keying conversation history/permissions. It describes Graph application permissions but does not establish distinct tenant-owner consent for identity correlation, data migration or disclosure. Cross-platform data movement is not authorized merely because API scopes exist.
2. **Files and sharing:** `experts/bridge/files-upload-download-ts.md` (blob `6f5bb460724bfebb9b7724fd56fbbf1c0d8edbe2`) discusses pre-authenticated file download URLs, Graph sharing links including anonymous scope, and direct channel file operations outside the personal-chat FileConsentCard flow. These require separate sender/recipient, destination, sharing-scope, and sensitive-data authority.
3. **Cloud and credential changes:** `experts/deploy/azure-bot-deploy-ts.md` (blob `0a7de69f9eaddb067e21648044cc16e960b0436a`) includes Entra app registration, credential reset, app-settings commands carrying secrets, cloud provisioning and deployment. `experts/deploy/aws-bot-deploy-ts.md` (blob `c665d944b8165229853f544dd87e1ce5fbf45ade`) includes IAM creation, bot credential handling, billable cloud deployment and CloudWatch alarm creation. Selection of a target or method is not authorization to execute these changes.
4. **User communications:** `experts/slack/web-api-proactive-ts.md` (blob `077c845059470b6ef33c7b08f0b8d0c91e8408c3`) gives patterns for proactive channel messages, scheduled messages, file uploads and deletion. These require distinct recipient/channel and communication authorization before execution.
5. **Routing/defaults:** `experts/bridge/cross-platform-advisor-ts.md` (blob `5330e68f51d64de73e2272bf574a519b50c5ba9f`) uses a "take all defaults" shortcut for migration design and writes project files. A default design choice cannot authorize identity disclosure, cross-tenant transfer, deployment or user communication.
6. **Positive safeguard:** `experts/security/secrets-ts.md` (blob `37fe0b8818ec11712eae2c83fa8fbf1ccf16ae55`) recommends Key Vault, managed identity, least privilege and secret-log redaction. Those are useful adaptation patterns but do not supply missing authorization gates elsewhere. The parent skill additionally says to ask users for **real secret values**, which conflicts with the repository's secure external-credential-path requirement.
