# Private qualification VM card (blank example only)

**DO NOT COMMIT A FILLED-IN CARD.** Store only in the owner's authorized
private host/memory store under its identity, consent, retention and access
controls. This blank template has no real account, credential or project data.

| Field | Private owner-supplied record |
| --- | --- |
| Project owning VM | NOT_RECORDED |
| Windows Hyper-V host, VM name and ID | NOT_RECORDED |
| CPU, static memory, Generation 2, disk capacities | NOT_RECORDED |
| OS version, evaluation license status and expiry | NOT_RECORDED |
| Approved ISO fingerprint and authority | NOT_RECORDED |
| Guest user identity and DPAPI credential location (NOT PASSWORD) | NOT_RECORDED |
| Host NIC count / guest Up NIC count / last inspected time | NOT_RECORDED |
| GPU partition devices after each restore | NOT_RECORDED |
| fresh-os checkpoint timestamp and parent | NOT_RECORDED |
| Subsequent named stage checkpoints and state | NOT_RECORDED |
| Toolchain/file hashes and staged input provenance | NOT_RECORDED |
| Native suite result, exact source, exit codes, timestamp | NOT_RECORDED |
| Exported evidence destination and SHA-256 readback | NOT_RECORDED |
| Known faults, recovery attempts, one-attempt sign-in result | NOT_RECORDED |
| Owner-approved retirement and storage-size report | NOT_RECORDED |

Check the actual state before every connection; do not infer networking
or GPU device removal from checkpoint names. Keep checkpoint lineage and
licensing grace distinct from product qualification and native test proof.
