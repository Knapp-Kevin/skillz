# Controlled multi-provider comparison

Do not manufacture a single ranking across unrelated product lines.
Only compare at the same abstraction layer and measurement conditions:
hosted API to hosted API, local checkpoint to local checkpoint, SDK contract
to SDK contract, and legal obligation to its actual jurisdiction.

For each event group, write: `decision variable; affected providers;
source and revision; comparability; unknowns; verification action`.

Separate:
1. Compatibility: public endpoint, version and actual client impact.
2. Operational economics: input/output billing dimensions, usage tiers,
   latency/performance tested under comparable conditions.
3. Model license and distribution: weight access versus reuse rights.
4. Security: reported issue versus shipped patch and host exposure.
5. Adoption: telemetry or independent evidence versus community buzz.

A comparison is UNCOMPARABLE when a relevant unit, workload, licensing
right, source revision or measured condition differs materially.
The correct response is a proposed head-to-head controlled experiment,
not invented normalization or confidence.

Multi-topic reports do not infer private relevance from a public query.
Use the user's supplied stack and objectives only within approved scope;
otherwise provide generic potential impact with NOT_ASSESSED status.
